# ADR-001 — Independent FormBridge Infrastructure Project

**Status:** Accepted (research-level decision, 13.11.2026)
**Context:** Feldexa 2.0 research Issue [#167](https://github.com/xxammaxx/Feldexa_2.0/issues/167), migrated to this repository from [Feldexa_2.0 PR #168](https://github.com/xxammaxx/Feldexa_2.0/pull/168) (commit `cb122fe2f96a8f5cbde2f075e0b6529342caf676`)
**Decision owners:** Repository owner (xxammaxx); recorded autonomously during authorized research continuation

## Decision

**FormBridge is an independent, reusable open-source software infrastructure project.** It lives in its own repository (`xxammaxx/FormBridge`), has no dependency on Feldexa-specific UI, application architecture, or private implementation details, and its future public interfaces (CLI, library APIs, machine-readable artifacts) must be usable by other applications and organizations.

**Feldexa 2.0 is the intended first application** — as a consumer of FormBridge interfaces, not as its host. It is **not integrated** and **not part of the funded scope**.

## Research scope (goals, NOT completed functionality)

- Static administrative PDF interpretation
- Semantic mapping to versioned FIM data-field identifiers
- Field-level provenance
- Confidence and UNKNOWN handling
- Human review of uncertain or critical mappings
- Reproducible validation
- Original-document integrity
- Offline-capable processing

Every one of these is a *research goal* documented in [`docs/research/technical-specification.md`](../research/technical-specification.md). Nothing is implemented; claims of capability are prohibited until artifacts exist that prove them.

## Consequences

1. **No production code from Feldexa.** FormBridge does not copy or import Feldexa 2.0 product code, specifications of its app architecture, or private implementation details.
2. **Interface-first thinking.** Interfaces are designed for adopters other than Feldexa (other citizen-facing apps, municipal tooling, research). Feldexa-specific requirements must be expressed as one consumer profile, never as hard-coded assumptions.
3. **Independence is verifiable.** The repository must remain standalone-buildable and runnable without Feldexa artifacts; validation includes an explicit independence check (V6 in `docs/validation/`).
4. **Funding separation.** Work done before a potential Prototype Fund grant (research, specification, repository setup) is *prior work*; funded work would be the module implementation under the documented boundary (`docs/funding/project-boundary.md`).
5. **Licensing remains an owner decision** (`docs/governance/license-decision.md` — OWNER_DECISION_REQUIRED).

## Alternatives considered

- **Module inside Feldexa 2.0** — rejected: would couple a reusable infrastructure artifact to one app, weaken reuse by other organizations, and blur funding-boundary accounting.
- **Fork of an existing project (e.g., Formularagent)** — rejected after source audit: none of the audited projects implements the researched chain; forking would inherit scope and license constraints not designed for this goal.
- **Delay repository until funding decision** — rejected: research evidence and reproducibility benefit from a public, citable home; the boundary document prevents misrepresentation of prior work as future funded work.

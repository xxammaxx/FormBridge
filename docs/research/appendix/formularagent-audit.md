## 1. Architecture summary (with evidence)

**Purpose (README.md:12):** "Der Formularagent vereinfacht die Überführung von Formularen aus unterschiedlichen Eingabeformaten: Excel-Modellierungstabelle, FIM und Form.io, in das von den zuvor genannten Serviceportalen verwendete JSON-Format. Alle Quellen laufen über eine gemeinsame Zwischenrepräsentation; die Erzeugung des Formular-JSON ist deterministisch und quellenunabhängig; ein weiteres Eingabeformat erfordert nur einen zusätzlichen Adapter."

**Stack:** Python ≥3.10, uv. Dependencies (`pyproject.toml:8-22`): beautifulsoup4, boltons, esprima (JS parsing), google-genai, jinja2, jsonschema, loguru, lxml, mistralai, openai, openpyxl, pytest, python-dotenv, pyyaml, requests, ruff, ty. Notably **pydantic is not a direct dependency** — it arrives transitively via `google-genai` (`uv.lock` includes `pydantic` under google-genai's deps), while `src/core/intermediate_form.py:5` and `src/shared/ozg_model.py:10` import it directly.

**Layered pipeline (README.md:69-81 documents it; code matches):**

1. **Entry point / CLI:** `src/convert.py` — `convert.py --source {excel|fim|formio} <file>`; dispatches via central registry `SOURCES` (`src/core/registry.py:119-123`) and per-source CLI flags; default schema `data/schema/revision_2/2.schema_corrected.json` (`convert.py:8-10`), default LLM `gemini-3-flash-preview` (`convert.py:11`).
2. **Per-source adapters** under `src/sources/{excel,fim,formio}/`, each with the same internal stages `read → preprocess → interpret → assemble → conditions` (e.g. `src/sources/fim/to_ir.py:12-33`: `read()` → `interpret()` → `assemble()` → `build_conditions()`).
3. **Intermediate representation (IR):** Pydantic model `src/core/intermediate_form.py` — `IntermediateForm` = metadata + `IRSection[]` + `IRGroup[]` + `IRElement[]` + `IRCondition[]` (lines 139-147). 18 field types incl. `text_input, select, file_upload, euro_betrag, kfz` (lines 7-25). `IRElement.source_id` = "Original-ID (z. B. FIM fimId)" (lines 52-54). `IRGroup.origin` and `IRCondition.origin` dicts exist (lines 91, 131) — but **`IRElement` has no `origin` field**. JSON Schema of the IR is generated to `data/schema/ir/intermediate_form.schema.json` (`src/generate_ir_schema.py`).
4. **Core builder:** `src/core/ir_builder/__init__.py` (`IRBuilder.build`, lines 34-71) — IR → OZG form dict, keeps a `field_registry` (original key → generated `fieldId`), applies conditions, group overrides, row layout, then runs report checks. Output wrapper: `{"engineVersion": "2", "id": f"1:{form.metadata.form_id}:1.0", "title": ..., "sections": [...]}` (lines 66-71).
5. **Output validation (3-stage):** `src/core/validation/validation.py:15-30` — JSON parse → `jsonschema` against the Formularschema → Pydantic `OZGModel` (a datamodel-codegen-generated model of `2.schema_corrected.json`, `src/shared/ozg_model.py:1-4`). Only when all three pass is the migration "successful" (`src/core/pipeline.py:78-79`).
6. **Migration report:** `src/shared/migration_report/migration_report.py` — class docstring line 36: `"Collects skipped/partial migration items for human review."` Two output lists `nicht_migriert` / `pruefen` (`to_dict`, lines 129-141); ~35 categories with list assignment in `src/shared/migration_report/report_kategorien.yaml` (311 lines).
7. **Post-processing:** `src/postprocessing/{validation_rule_setter,personentyp_split,standardblock}` — README.md:115: "wurden für das Input-Format Form.io erstellt und wurden nicht mit anderen Formaten getestet". Standardblock uses an LLM classifier producing an inspectable `EditPlan` (`src/postprocessing/standardblock/classify_llm.py:166-170`).
8. **LLM layer:** `src/shared/llm/` — Gemini (Google cloud, `gemini.py`), GPT and Mistral clients exist but `llm.py:3` pins `LLM = Gemini`. LLM is used for free-text visibility-condition translation (FIM: `sources/fim/conditions/build.py:62-78`, formio: `sources/formio/conditions/translate.py:209`) and standardblock classification. Rule-based paths work without LLM (`--skip-conditions`, `registry.py:20-25`).
9. **Run artifacts:** each run writes `output/<source>/<form>/<timestamp>/` with `intermediate_form.json`, `migration_report.json`, `ozg_form.json`, `params.json`, `pipeline.log` (`src/core/pipeline.py:43-94`; README.md:105-111).

**No HTTP/REST API**: no flask/fastapi/uvicorn anywhere in `src/`; it is a headless CLI + importable library modules (README.md:45: "Headless-Werkzeug ohne eigene Benutzungsoberfläche").

## 3. Significant findings (exact paths/lines)

1. **`src/core/ir_builder/sections.py:159-160`** — FIM identifiers survive into the product JSON: `if el.source_id: field["fimId"] = el.source_id`. This is the only place a FIM data-field ID reaches the output.
2. **`src/core/intermediate_form.py:52-54`** — IR reserves provenance-by-identifier at element level (`source_id` "Original-ID (z. B. FIM fimId)") but **no `origin` dict on `IRElement`** — per-field source coordinates exist only in the migration report, not in IR or output JSON.
3. **`src/shared/llm/gemini.py:22-52`** — `_upload_file(pdf_file)` and a `pdf_file` parameter on `prompt()` exist, but **no adapter ever passes a PDF**; it is dormant capability aimed at a possible future PDF path, using the Gemini Files API (cloud).
4. **`pyproject.toml` pytest section vs. repo** — the referenced `test/replay_llm` module (ReplayLLM/golden harness) is absent from the published tree; LLM-dependent steps are therefore neither tested nor evaluable from this snapshot alone.
5. **`src/sources/fim/read/read.py:243-246`** — the only explicit xdf2/xdf3 distinction (rule text element name). All other parsing is version-agnostic localname matching, so xdf2 and xdf3 work without declared version detection.
6. **`src/shared/migration_report/migration_report.py:101-113`** — unknown report categories fall back to list `nicht_migriert` with a warning ("Kategorie … fehlt in report_kategorien.yaml — sie erscheint unübersetzt im Report") — a deliberate safety net.
7. **`src/core/registry.py:119-123`** — exactly three sources; adding a fourth (e.g. PDF) is a documented, code-verified extension point (`convert.py` needs no change, line 42-43 uses `SOURCES[known.source].add_arguments`).
8. **`data/schema/`** — 8 schema variants across `revision_1`, `revision_2`, `ir`; the *target* schema versioning is file-based, selected via `--schema` (`convert.py:33-35`), no automatic schema-version negotiation.
9. **`src/core/validation/validation.py:46`** — `validate_against_all` uses a relative glob `Path("../data/schema")`, which only works from specific CWDs — minor robustness defect, function appears unused by the CLI path.
10. **`src/sources/fim/read/raw.py:52-56`** — `group_path` documented as "nur für Report-Traceability … Fließt nicht in ``group_ref``/fg-id ein, ändert also nie den tatsächlichen OZG-Output" — provenance deliberately kept out of functional output.

## 4. Assessment (research questions)

**Q1: Does Formularagent implement legacy-static-PDF → versioned-FIM-field-ID mapping with coordinates, provenance, confidence, human review?**

**No.** Component by component:
- **PDF input:** not implemented — the three adapters read xlsx, xDatenfelder XML, and form.io JSON (`registry.py:119-123`); the only PDF code is the unused `Gemini._upload_file` (`gemini.py:22-40`).
- **Coordinates:** not implemented — layout is 12-column-grid slots (`intermediate_form.py:67-68`, `layout.py:49-88`), no x/y/visual data anywhere.
- **FIM field IDs:** only as *pass-through from FIM input* (`interpret.py:86` → `sections.py:159-160`), never as a *target vocabulary* that a non-FIM source is mapped onto. README.md:8 states the boundary explicitly: "Die fachliche und rechtliche Modellierung der Datenfelder bleibt Aufgabe etablierter Methoden wie des FIM-Bausteins „Datenfelder" — der Formularagent operiert ausschließlich auf der technischen Ebene der Formularrepräsentation."
- **Provenance:** report-level only (`migration_report.py:69-80`, `excel/origin.py`), plus FIM `report_id`/`group_path` traceability (`read/raw.py:46-56`); not embedded per field in the output.
- **Confidence:** categorical two-list model (`nicht_migriert`/`pruefen`, `migration_report.py:129-141`), no numeric scores.
- **Human review:** report consumption + downstream Formulardesigner (README.md:40), no review tooling here.

**Q2: Could its FIM/XDF handling be reused as a library for such an adapter (is integrating existing tools sufficient)?**

**Partially — the scaffolding is genuinely reusable, the domain gap is not covered:**
- **Reusable as-is:** (a) the xDatenfelder reader — namespace-agnostic, xdf2+xdf3, genericode codelist resolution (`src/sources/fim/read/read.py`, `codelist_loader.py`) — could be repurposed to *read* a FIM schema as a target vocabulary; (b) the IR + its published JSON Schema (`core/intermediate_form.py`, `data/schema/ir/intermediate_form.schema.json`) as an adapter target; (c) the `MigrationReport` with YAML-configurable categories and origin tracking (`migration_report.py`, `report_kategorien.yaml`) as a provenance/review channel; (d) the 3-stage output validation (`validation/validation.py`); (e) the documented adapter contract read→preprocess→interpret→assemble→conditions + registry plugin pattern (README.md:67-81, verified in `registry.py`). A PDF→IR adapter could be added "without touching core".
- **Gaps an integration would have to fill:** pixel/region coordinates are unrepresentable in the IR (`width`/`row_slot` only — `intermediate_form.py:67-68`); no numeric confidence channel; no per-element `origin` in IR; no FIM-identifier *resolution* service (nothing looks up data-field definitions by URN beyond the single input document and its codelists — `read.py` parses one `stammdatenschema` per file); no FIM/XDF *emission* or XSD validation (output is OZG form JSON only); `fimId` emission assumes the FIM ID came from the input, so a PDF→FIM-ID mapper would need new IR plumbing (`source_id` semantics would need redefinition for non-FIM sources). Conclusion: **integration of existing tools covers roughly the report/validation/IR scaffolding; the PDF/OCR extraction, coordinate capture, confidence scoring, and FIM-ID resolution layers would have to be built new.**
